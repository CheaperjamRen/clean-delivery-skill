# Clean Delivery Rules

## 交付面

- 标题、文件名、章节名和 PR 标题描述成果本身。
- 正文、注释和交付回报呈现最终状态、必要证据、事实限制和可点击链接。
- 草稿、候选方案、失败尝试和过程记录放在独立工作记录中。

## 范围

- 先确认当前目标和停止条件。
- 采用满足当前条件的最小正确改动。
- 额外想法进入待办，等待明确采纳。
- 用户修正方向后，把新方向当作当前规格，交付面回到最终状态。

## 各类产物

- 注释写 non-obvious reason、边界或失效条件。
- PR、Commit 和回报写最终行为、验证结果、风险与阻塞项。
- 文档、报告、PPT 和导出文件按最终结构组织。

## 保留事实

失败测试、未完成项、数据缺口、风险、权限要求和用户确认动作保持简洁可核验。审计、迁移、对比和复盘内容进入单独记录。

## 交付前检查

- [ ] 标题和文件名像成果本身。
- [ ] 内容没有删改历史、候选路径或自我辩护。
- [ ] 范围内结果完整，范围外想法离开交付面。
- [ ] 验证、限制、风险和链接可核验。

触发词：`干净交付`、`锁定范围`、`只报结果`、`保留关键理由`。
